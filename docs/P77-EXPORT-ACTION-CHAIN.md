# P77 — Approved GUI action → newly generated export → independent P76 validation

P77 is a **generic orchestrator** around existing P39/P65 native GUI actions and P76 output assertions. It is not a universal automatic button-discovery engine and cannot infer export functionality for arbitrary plugins.

## Invocation

On a Windows test host, write an approved chain JSON:

```json
{
  "schema": "125a-export-action-chain-v1",
  "workflow": { "...": "exact existing 125a-gui-workflow-v1 manifest" },
  "export": { "...": "exact existing 125a-export-artifact-oracle-v1 contract" }
}
```

The two nested objects **must be replaced** with complete validated contracts from `tests/run_gui_workflow.py` and `docs/P76-WAV-MIDI-ORACLES.md`. This schematic JSON is not executable as-is.

```powershell
python tests/run_export_action_chain.py --chain C:\QA\approved-chain.json --out C:\QA\p77-results
```

All output paths from the export contract must be **absent before the first click**; P77 never removes or overwrites an existing output. Use a fresh unique output destination for each run. Preflight validates native module identity, host and every GUI action as well as the independently approved output hash/metadata oracle. The approved native GUI actions execute once via the existing host. Only if all actions pass, newly appearing WAV/MIDI files are validated by P76. Missing, stale, corrupt or mismatched output fails closed. Reports are written to `EXPORT-ACTION-CHAIN-RESULT.json` and the nested action/artifact evidence folders. Release approval is always false.

## Boundaries

- No plugin-specific C++ or QA source logic. Product teams supply their own reviewed GUI coordinates, independent action oracles and expected export bytes.
- A specific native action must actually produce the specified files. A file generated by an unrelated process or a test fixture does **not** prove a plugin exporter; therefore the current Windows CI exercises mock orchestration and negative paths, not a real exporter.
- For arbitrary Save As dialogs, host-level export APIs, DAW routing, native audio capture, or export operations without observable GUI controller transitions, further generic adapters are needed.
- P77 is integrated into the P65 product plan as case kind `export_action_chain` and can be dispatched by P74 when the approved plan includes it. The nested chain is the case `contract`. The case checks both native action count and output artifact count. It does not prove complete product behavior, ASIO hardware coverage or release readiness.

## CI evidence boundary

The P77 Windows regression and P65 adapter tests use mocked GUI actions and mock export files. These validate strict dispatch, stale-file refusal and fail-closed result accounting, **not** a completed native VST3 export. A real Windows host test invoking a genuine exporter and confirming the resulting WAV/MIDI files remains a required acceptance criterion.
